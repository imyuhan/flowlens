# FlowLens ch02 Checklist

> 每一项通过**运行代码或观察行为**来验证，不通过逐行读代码判断。
> 条目与实现解耦：重命名文件或移动函数不应导致任何一项失败。
> 对应 spec：`docs/ch02/01/spec.md`。

## 分析主路径（LLM）

- [ ] **语义识别生效** —— 提交不含规则引擎词典词汇的同义改写描述（如「我天天盯着销售表，把数字抄进周报」），能识别出可自动化任务；而同一输入交给本地规则分析时识别不出（对应 spec EA1）：建议用规则引擎直接跑同一输入做对照，两者结果差异即为证据
- [ ] **返回结构完整** —— 提交示例描述后，结果含概览统计（片段总数 / 可自动化数 / 平均分 / 每周节省工时）与任务列表，每个任务含任务名、优先级分、三维度分、判定依据、自动化建议、SOP 四段、可复用 Prompt（对应 EA2）
- [ ] **判定依据是理由而非关键词罗列** —— 任务的依据标签读起来是语义判断（如「每日重复的机械整理」），而不是词典命中词（如「每天」「整理」）（对应 F3/EA3）
- [ ] **按优先级降序** —— 结果中任务的优先级分数从左到右/从上到下不递增（对应 EA3/F4）
- [ ] **分数在合法区间** —— 所有任务的优先级分与三维度分都在 0–100 之间，无小数、无越界（对应 F2）
- [ ] **等待期间有反馈** —— 从点击「开始分析」到结果出现期间，界面持续显示进度反馈，不出现无响应空白（对应 N12）

## 降级路径

- [ ] **服务不可达时仍出结果** —— 断网或让分析接口返回失败后提交描述，页面仍展示完整结果，并明确标注结果来自本地规则分析（对应 EB1/F5）
- [ ] **降级原因可读** —— 降级提示是用户能懂的中文原因（如「AI 暂不可用」），不出现错误堆栈、状态码或供应商原始报错（对应 N8）
- [ ] **畸形输出触发降级而非崩溃** —— 让分析接口返回非法结构（截断的 JSON / 字段类型错误 / 空响应），页面不白屏、不报错，转为展示本地规则结果或可读提示（对应 EB2）
- [ ] **本地开发默认走降级** —— 只启动前端开发服务器（不启动服务端函数）时，页面仍可完整使用，走本地规则路径（对应 F5）

## 边界与安全

- [ ] **超长输入被拒绝且不耗额度** —— 提交超过 2000 字的输入，收到明确提示，且分析接口在调用模型之前就已返回（对应 EC1/F6）：可通过服务端日志或额度消耗确认未触发模型调用
- [ ] **过短输入不发请求** —— 提交去空白后少于 10 字的内容，就地提示且不产生任何网络请求（对应 F6）：在浏览器网络面板确认无请求发出
- [ ] **客户端不含凭据** —— 检查打包后的前端 JS 与所有网络响应，找不到任何密钥、token 或可直接调用模型服务的凭据（对应 EC2/F7）
- [ ] **仓库不含凭据** —— 在工作区与 git 历史中检索，找不到任何 API key 或密钥（对应 EC3/N7）
- [ ] **历史数据不出现在网络请求中** —— 抓取分析过程的全部网络请求，请求体只含用户当下输入的文本，不含任何历史记录内容（对应 EC4/N9）
- [ ] **限流生效** —— 部署环境下短时间内连续请求超过阈值后，后续请求被拒绝并返回可读提示（对应 EC5/N4）：限流规则在部署平台上配置，需部署后验证

## 历史记录

- [ ] **分析后跨刷新保留** —— 完成一次分析后刷新页面，历史列表里仍有该条记录（对应 ED1/F8）
- [ ] **点击历史可还原** —— 点击历史条目，结果区显示该条当时的完整结果，与保存时一致，含来源标注（对应 ED2/F9）
- [ ] **还原不消耗额度** —— 从历史还原结果时未产生任何模型调用（对应 F9）：在网络面板确认无相关请求
- [ ] **删除单条生效且持久** —— 删除某条历史后该条消失、其余保留，刷新页面后确认未被恢复（对应 ED3/F10）
- [ ] **清空全部生效且持久** —— 清空历史后列表为空，刷新页面后仍为空（对应 ED4/F10）
- [ ] **清空需二次确认** —— 点击「清空全部」不会立即清空，需要再次确认（对应 F10）
- [ ] **存储不可用时不崩** —— 在禁用本地存储的环境（隐私模式 / 手动禁用）下打开页面，分析功能照常可用，历史区域给出「不可用」提示，页面不白屏（对应 ED5/N11）
- [ ] **上限 50 条且用户知情** —— 连续保存超过 50 条后只保留最新 50 条，且界面上能看出存在条数上限（对应 ED6/F11）
- [ ] **来源标注随历史保留** —— 降级产生的历史条目，还原后仍显示「本地规则分析」，不会变成「AI 分析」（对应 F8）

## 集成

- [ ] **契约只有一处定义** —— 分析接口返回的结构与前端消费的结构来自同一份类型定义，不存在两边各写一份的情况：改一处类型，另一处会立刻报类型错误
- [ ] **规则引擎行为未变** —— 用与 ch01 相同的输入调用规则引擎，输出与 ch01 完全一致（`rationale` 字段除外）
- [ ] **页面渲染结果区未被破坏** —— 用渲染快照工具对比改动前后，规则路径下任务卡片的渲染输出与 ch01 逐字节一致
- [ ] **加载态无重叠延迟** —— 分析流程中不存在人为的固定延时（ch01 的假加载态已移除），响应耗时全部来自真实调用

## 编译与测试

- [ ] **类型检查通过** —— 类型检查命令通过，且服务端函数目录确实被纳入检查（故意引入一个类型错误能报出来）
- [ ] **生产构建通过** —— 生产构建命令成功，产出静态资源目录
- [ ] **冒烟测试通过** —— 冒烟测试全部通过，且包含输出校验器对畸形输入的断言
- [ ] **渲染快照可生成** —— 快照脚本能完整输出所有区块（含来源标注与历史面板的各状态）

## 端到端场景

- [ ] **场景 1：首次使用完整流程** —— 打开页面（空态）→ 点「填入示例」→ 点「开始分析」→ 等待期间有进度反馈 → 出现概览条与任务卡片，卡片含判定依据 → 卡片上标注来源 → 复制 Prompt 后按钮显示「已复制」
- [ ] **场景 2：降级完整流程** —— 断开服务端 → 提交描述 → 页面仍出结果 → 明确标注为本地规则分析 → 提示原因可读 → 功能（复制 Prompt 等）全部照常可用
- [ ] **场景 3：历史跨刷新完整流程** —— 分析一次 → 刷新页面 → 历史入口显示条数 → 打开抽屉看到该条 → 点击还原结果 → 删除该条 → 刷新确认已删除 → 再分析一次并清空全部 → 刷新确认仍为空
- [ ] **场景 4：移动端不崩** —— 在 320px 宽度下：无横向滚动条、文字不溢出、按钮可正常点击、历史抽屉全屏可滚动、任务卡片纵向堆叠正常（对应 JA4/N1）
- [ ] **场景 5：超长输入边界** —— 粘贴一段超过 2000 字的文本 → 点分析 → 收到明确提示 → 截短到合法长度后重新分析成功

## 项目交付

- [ ] **公网可访问** —— 部署后的 URL 能直接打开并使用（对应 JA2）
- [ ] **部署配置正确** —— 部署平台已配置模型服务的运行时绑定，线上能走通 LLM 路径而非始终降级（对应 JA2）
- [ ] **README 已更新** —— 英文 README 的 known limitations 不再声称「纯规则」或「确定性」，并说明了免费额度耗尽会降级、历史仅存本地、上限 50 条（对应 JA3）
- [ ] **本地开发说明准确** —— README 说明了只跑前端与跑完整全栈两种方式的区别（对应 JA3）

## 已知的验证限制

以下条目**在特定条件下无法完成验证**，需如实标注而非默认通过：

- **EC5（限流）** —— 依赖部署平台的限流规则配置，只能在部署后验证
- **JA2（公网 URL）与部署配置** —— 需要用户在 Cloudflare dashboard 配置 Workers AI binding 并完成部署
- **EA1（语义识别对照）** —— 需要实际的模型调用；若免费额度耗尽，只能验证降级路径
  
若某项因上述原因无法验证，报告中标记为「未验证」并说明原因，不得以「应该没问题」代替。
