# FlowLens ch02 Spec

> 承继 `docs/ch01/01/spec.md`。ch01 交付了纯前端、纯规则的 MVP 并已上线；ch02 把识别与分析层换成 LLM，规则引擎降级为兜底路径，并新增浏览器本地历史记录。
>
> 硬性约束延续 `CLAUDE.md`：公网可访问、英文 README、移动端不崩、不提交任何 API key。

## 背景

ch01 的 FlowLens 靠三个关键词词典（重复性 16 词、耗时性 28 词、规则明确度 24 词）+ 子串匹配 + 线性加权打分 + 固定模板产出结果。它能跑、确定性好、零成本，但受限于规则的本质 —— ch01 自己在 README 里列出的第一条已知局限就是：

> **Rule-based, not semantic.** Matching is keyword-driven, so it cannot understand context or paraphrase. It may miss automatable tasks that use different wording, or flag a segment purely because it contains a trigger word.

具体表现有三点：

- **词典外的同义改写一律漏判** —— 「我天天盯着销售表，把数字抄进周报」不含「每天」「整理」「复制」中的任何一个词，ch01 返回空结果
- **反向误判** —— 一句话只因为恰好出现「定期」就被判为可自动化，哪怕语境无关
- **文案与原文脱节** —— SOP 与 Prompt 是模板拼接，换个输入还是那句「收集并准备原始数据」

ch02 用 LLM 替换这一整层。同时新增本地历史记录：ch01 刷新页面即丢失全部结果，用户无法回看上一次分析。

### 前置条件

需要**阿里云百炼（DashScope）的 API key**，配置为 Cloudflare Pages 项目的环境变量；本地开发放项目根目录的 `.dev.vars`（已加入 `.gitignore`）。

模型通过 **OpenAI 兼容协议**调用，端点 / 模型名 / 密钥三项均可由环境变量覆盖，因此更换服务商无需改代码：

| 环境变量 | 默认值 |
|---|---|
| `OPENAI_API_KEY` | 无（必填） |
| `OPENAI_BASE_URL` | `https://dashscope.aliyuncs.com/compatible-mode/v1`（北京站） |
| `OPENAI_MODEL` | `qwen-plus-2025-07-28` |

> **变更记录**：本节原为「无需任何 API key，使用 Cloudflare Workers AI 的运行时绑定（`env.AI`）」。因该路径未能调通，改为 OpenAI 兼容协议调用百炼。

## 目标

- **G1**：用 LLM 完成语义级工作流分析，替换关键词匹配、线性打分与模板文案
- **G2**：ch01 规则引擎原样保留，作为 LLM 路径不可用时的降级方案
- **G3**：数据契约与页面结构延续 ch01，页面改动最小化
- **G4**：模型调用只发生在服务端运行环境；客户端不持有任何凭据，也不直接调用模型服务
- **G5**：分析结果持久化到浏览器本地，可查看、可删除

## 功能需求

### A 组：LLM 分析

- **F1**：用户提交工作描述后，系统将整段文本发送至服务端分析接口，由 LLM 完成片段切分、可自动化任务识别、优先级评分与文案生成，并返回完整分析结果
- **F2**：返回结果的结构与 ch01 契约一致 —— 一份概览统计（片段总数、可自动化任务数、平均优先级分、估算每周节省工时）+ 一组任务；每个任务含任务名、优先级评分（0–100）、三维度分、判定依据、自动化建议、SOP（触发 / 输入 / 步骤 / 输出）、可复用 Prompt
- **F3**：每个任务须给出「为什么判定为可自动化」的理由，而非仅罗列命中的关键词
- **F4**：任务按优先级评分降序返回
- **F5**：当 LLM 路径失败（网络错误、超时、返回内容不符合结构、免费额度耗尽）时，系统自动改用本地规则引擎完成分析，并把「本次结果来自降级路径」告知用户
- **F6**：分析接口对超长输入（超过 2000 字）拒绝处理并返回可读提示，且不消耗 LLM 调用
- **F7**：模型调用仅发生在服务端运行环境；客户端代码、网络响应与仓库中不含任何凭据，也不存在可直接调用模型服务的入口

### B 组：历史记录

- **F8**：每次分析完成后，系统自动保存一条历史记录 —— 输入文本 + 完整结果快照 + 时间戳 + 结果来源（LLM 分析 / 本地规则降级）；仅存于用户浏览器本地，不上传服务端
- **F9**：用户可查看历史列表（按时间倒序），点击任一条即还原当时那份完整结果，无需重新分析、不消耗 LLM 额度
- **F10**：用户可删除单条历史记录，也可清空全部历史；删除后本地不留残余，刷新后不会复现
- **F11**：历史记录上限 50 条，超出时淘汰最旧的记录；界面上须让用户知道这一行为，而非静默丢弃

## 非功能需求

- **N1**：移动端不崩 —— 320px 宽度无横向滚动条，文字不溢出不换行错乱（延续 ch01）
- **N2**：LLM 路径在正常网络下应在 **1 分钟**内给出结果；超时即降级，不让用户无限等待。服务端上游超时 55 秒、客户端 65 秒，服务端须**小于**客户端，否则客户端会先触发降级、`timeout` 原因失真
  - 阈值依据（实测）：单任务输入约 9 秒，4 任务输入约 22 秒；输出量随任务数近似线性增长，原定 25 秒服务端超时对 4 任务输入仅剩 3 秒余量，会稳定误杀
- **N12**：等待期间界面须持续给出进度反馈 —— 单次调用可能耗时 10–30 秒，界面不得在这段时间内呈现无响应的空白
- **N3**：**主动放弃 ch01 的确定性承诺** —— LLM 非确定性，相同输入两次结果可能不同。ch01 spec 的 N3（确定性）就此作废，README 的 known limitations 必须同步改写
- **N4**：防滥用 —— 服务端按来源 IP 限流（部署平台规则）+ 输入长度上限 2000 字
- **N5**：UI 全中文（延续 ch01）
- **N6**：部署形态延续 ch01（静态托管 + 同源服务端函数共存），静态导出能力保留
- **N7**：仓库不含任何凭据；本地开发的密钥存放于 `.dev.vars`（已加入 `.gitignore`），仓库中只提交不含真实值的 `.dev.vars.example` 模板
- **N8**：降级必须优雅 —— LLM 失败不得导致白屏，不得把错误堆栈或供应商原始报错暴露到页面
- **N9**：历史数据仅存于浏览器本地，不上传服务端；清除浏览器数据即彻底消失
- **N10**：存储占用可控 —— 单条结果快照不超过约 20KB，50 条上限下总占用远低于 localStorage 的 5MB 限制
- **N11**：历史功能的任何失败（隐私模式禁用本地存储、配额写满、已存数据损坏）都不得导致页面崩溃 —— 应降级为「历史不可用」并提示，分析功能本身照常可用

## 不做的事

- 不修改 ch01 规则引擎的内部逻辑（原样保留，仅作为降级路径）
- 不做流式输出（结果必须完整才可渲染，结构化场景收益小）
- 不做多轮追问 / 对话式澄清
- 不做用户账号、不做 BYOK（用户自带 key）
- 不做多 provider 切换，只接 Gemini
- 不做人机验证（Turnstile 等）
- 不做 prompt 评测框架 / 打分对比面板
- 不做深色模式 / 国际化 / 文件上传
- 不做历史记录的跨设备同步、导出分享、重命名备注

## 验收标准

### LLM 路径生效（EA）

- **EA1**：对**不含 ch01 关键词表词汇**的同义改写输入（如「我天天盯着销售表，把数字抄进周报」），LLM 路径识别出可自动化任务，而规则路径漏判 —— 证明语义识别真的生效（对应 F1/F3）
- **EA2**：对 ch01 约定示例，LLM 路径返回的概览统计与任务列表结构完整、字段与契约一致（对应 F2）
- **EA3**：任务按优先级降序，且每个任务带判定理由（对应 F3/F4）

### 降级路径（EB）

- **EB1**：制造 LLM 失败（错误凭证 / 断网 / 强制超时）→ 页面仍展示完整结果，并明确标注结果来自本地规则（对应 F5/N2）
- **EB2**：制造 LLM 返回非法结构（畸形响应）→ 触发降级，而非崩溃或白屏（对应 F5/N8）

### 边界与安全（EC）

- **EC1**：输入超过 2000 字 → 返回可读提示，且未产生 LLM 调用（对应 F6/N4）
- **EC2**：检查客户端 JS bundle 与网络响应 → 不含任何凭证（对应 F7）
- **EC3**：在仓库与 git 历史中搜索 → 无 API key（对应 N7）
- **EC4**：抓取分析过程的网络请求 → 只有用户输入文本，不含任何历史记录数据（对应 N9）
- **EC5**：部署环境下超过速率阈值的连续请求被拒绝，并返回可读提示（对应 N4；限流规则在部署平台上配置，需部署后验证）

### 历史记录（ED）

- **ED1**：分析一次后刷新页面 → 历史列表仍有该条，点击可还原完整结果（对应 F8/F9）
- **ED2**：点击某条历史 → 结果区显示该条结果，与保存时一致，含来源标注（对应 F9）
- **ED3**：删除单条 → 该条消失、其余保留、刷新后仍已删除（对应 F10）
- **ED4**：清空全部 → 列表为空，刷新后仍为空（对应 F10）
- **ED5**：在禁用本地存储的环境（隐私模式 / 手动禁用）下 → 页面可正常分析，仅提示历史不可用，不白屏（对应 N11）
- **ED6**：连续保存超过 50 条 → 仅保留最新 50 条，最旧的被淘汰且界面有提示（对应 F11）
