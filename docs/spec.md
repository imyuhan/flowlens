# FlowLens Spec

## 背景

很多职场人的日常工作里，混着一批「重复、耗时、规则明确」的任务：整理数据、汇总进度、按条件分流工单、导出报表核对异常等。这些任务机械化程度高，是自动化的最佳候选，但当事人往往意识不到、也不会把判断依据写成可执行的步骤。

FlowLens 是一个轻量的 AI 工作流分析工具：用户输入一段日常工作描述，系统识别其中可自动化的任务，并给出自动化建议、优先级评分、SOP 和可复用 Prompt，帮助用户把「模糊的感觉」变成「可执行的自动化方案」。

## 目标

- 用户输入一段日常工作描述，系统识别其中重复、耗时、规则明确的任务
- 为每个可自动化任务输出：任务名、优先级评分、命中维度、自动化建议、SOP、可复用 Prompt
- 纯前端实现，无后端、无数据库、无 LLM 调用、无 API key，分析即时且结果确定
- 满足 CLAUDE.md 的硬性要求：公网可访问、英文 README、移动端不崩、不提交任何 API key

## 边界与分工

FlowLens 由两部分组成，分工如下：

| 部分 | 内容 | 实现方 |
|------|------|--------|
| 分析引擎 | 规则匹配、三维度打分、自动化建议 / SOP / Prompt 文案生成 | 本 spec 的实现者（Claude） |
| 前端页面 | 输入区、分析触发、概览条、任务卡片、复制等 UI | Codex（本 spec 只给出「页面要求」，不写页面实现） |

- 分析引擎是纯函数模块，前端页面通过一个稳定的数据契约调用它（契约在 plan.md 定义）
- 本节「前端页面需求」即交给 Codex 的实现要求；「分析引擎需求」是本实现者的开发要求

## 分析引擎需求

- E1: 接收一段文本，切分为任务片段，识别其中可自动化的任务（重复、耗时、规则明确）
- E2: 对每个片段在三个维度打分（重复性 / 耗时性 / 规则明确度，各 0–100），加权得到 0–100 的优先级评分
- E3: 为每个可自动化任务生成：自动化建议列表、SOP（触发条件 / 输入 / 步骤 / 输出）、可复用 Prompt
- E4: 输出概览统计：任务片段总数、可自动化任务数、平均优先级分、估算每周节省工时
- E5: 边界处理：空白或过短输入返回空结果；任何输入不抛异常；相同输入产生相同输出

## 前端页面需求（交给 Codex）

- P1: 提供文本输入区接收工作描述，并提供「填入示例」按钮（一键填充预置示例）
- P2: 提供「开始分析」触发分析；分析期间进入加载态（按钮禁用或显示进行中）
- P3: 渲染概览条：可自动化任务数、平均优先级分、估算每周节省工时
- P4: 渲染任务卡片列表，按优先级评分降序；每张卡片含任务名、评分、命中维度标签与关键词、自动化建议、SOP、可复用 Prompt
- P5: 可复用 Prompt 支持一键复制到剪贴板，复制后显示「已复制」反馈
- P6: 处理完整状态：空态（首次进入）、加载中、有结果、无命中（「未识别到可自动化任务」）、输入过短（就地提示）

## 非功能需求

- N1: 移动端不崩（页面）：320px 宽度无横向滚动条，文字自动换行不溢出，按钮触达面积足够
- N2: 纯前端（引擎 + 页面）：无后端、无数据库、无 LLM、无 API key，分析在浏览器内即时完成
- N3: 确定性（引擎）：相同输入产生相同输出
- N4: UI 全中文（页面）
- N5: 可部署到 Vercel / Cloudflare Pages / Netlify 等静态托管，公网可访问
- N6: 轻量，1 天内可交付

## 不做的事

- 后端 / API Route / 数据库 / 持久化（MVP 不保存历史记录）
- 登录、鉴权、多用户
- 多页面、路由、导航
- 任何 LLM / API key 相关逻辑
- 文件上传、富文本、拖拽
- 国际化（UI 写死中文）
- 深色模式

## 验收标准

### 分析引擎（本实现者验证，运行 smoke 脚本）
- EA1: 输入预置示例描述 → 引擎返回至少一个可自动化任务，且带 0–100 优先级评分（对应 E1/E2）
- EA2: 每个任务含自动化建议、SOP（触发/输入/步骤/输出四段）、可复用 Prompt（对应 E3）
- EA3: 概览统计字段正确（任务片段数、可自动化数、平均分、节省工时）（对应 E4）
- EA4: 过短/空白输入返回空结果且不抛异常；闲聊输入返回空任务（对应 E5）
- EA5: 任务按优先级评分降序（对应 E2/E4）

### 前端页面（Codex 实现后按此验收）
- PA1: 首次进入为空态；点击「填入示例」后输入区出现预置示例文本（对应 P1/P6）
- PA2: 输入预置示例 → 点「开始分析」→ 出现概览条和至少一张任务卡片（对应 P2/P3/P4）
- PA3: 每张卡片完整含任务名、评分、命中标签与关键词、建议、SOP、可复用 Prompt，且降序排列（对应 P4）
- PA4: 点击「复制」后剪贴板内容等于该 Prompt，且按钮短暂显示「已复制」（对应 P5）
- PA5: 输入去空白后少于 10 字 → 就地提示且不触发分析；输入闲聊 → 显示「未识别到可自动化任务」（对应 P6）

### 项目交付（CLAUDE.md 硬性要求）
- JA1: `npm run build` 通过，`npm run dev` 能打开页面（对应 N6）
- JA2: 部署后提交一个公网可打开的 URL（对应 N5）
- JA3: 仓库根目录存在英文 README（项目介绍 / 本地运行 / 技术栈 / known limitations）
- JA4: 仓库不含任何 API key（对应 N2）
